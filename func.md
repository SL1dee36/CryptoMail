## 1.2. Базовые сквозные сценарии (Use Cases)

### Сценарий 1: Регистрация нового пользователя
1. Контроллер `main.py:register_action` получает данные формы.
2. Вызывает `auth_service.py:validate_registration_inputs`, проверяя регулярные выражения логина, email и пароля.
3. Вызывает `auth_service.py:register_user`:
   * Вырабатывает 16-байтную криптостойкую соль $S \in_R \{0, 1\}^{128}$.
   * Вычисляет хеш пароля с помощью `streebog.py:pbkdf2_streebog512(password, salt, iterations=1000)`.
   * Генерирует ключевую пару ЭЦП через `ecp.py:generate_ecp_keypair()`.
   * Выпускает самоподписанный сертификат пользователя через `ecp.py:issue_self_signed_certificate()`.
   * Генерирует или извлекает из пула пару ключей RSA нужной разрядности (`rsa32k.py:get_or_create_rsa_keypair(key_size)`).
   * Формирует 5 случайных 8-значных резервных кодов восстановления (Recovery Codes).
   * Создает объект `User`. При присвоении закрытых ключей и кодов восстановления сеттеры модели прозрачно шифруют их через `db_cipher.py:encrypt_db_field()` (ГОСТ «Кузнечик» в режиме CBC).
   * Сохраняет пользователя в БД через `db.commit()`.

### Сценарий 2: Отправка защищенного сообщения
1. Пользователь или фоновая задача инициирует вызов `message_service.py:send_message`.
2. Проверяются полномочия отправителя (роль `guest` отклоняется).
3. При наличии у отправителя закрытого ключа ЭЦП:
   * Генерируется дайджест исходного текста через `streebog.py:streebog512`.
   * Накладывается подпись кривой SECP384R1 через `ecp.py:sign_message`.
4. В зависимости от выбранного протокола шифрования:
   * **RSA (включая RSA-32K)**: Загружается открытый ключ получателя `recipient.rsa_public_key`, вызывается `rsa32k.py:rsa_encrypt_hybrid(pub, body_bytes)`. Формируется случайный ключ «Кузнечика», данные шифруются в CTR, а сессионный ключ оборачивается RSA-OAEP.
   * **STREEBOG-512**: Вызывается `message_service.py:encrypt_message_streebog`. Генерируется соль и IV, вычисляется ключ через PBKDF2-Стрибог, данные шифруются в CTR, рассчитывается имитовставка HMAC-Стрибог-512.
   * **KUZNYECHIK-256**: Вызывается `message_service.py:encrypt_message_kuznyechik`. Формируется 256-битный симметричный ключ и IV, данные шифруются в CBC с набивкой PKCS#7.
5. Создается запись `Message`. Тема, шифротекст и ключевой бандл шифруются на уровне БД шифром «Кузнечик».

# Глава 2. Криптографическое ядро: алгоритмические модули

## 2.1. Модуль `crypto/kuznyechik.py`

Реализует блочный шифр ГОСТ Р 34.12-2015 («Кузнечик») с размером блока 128 бит и ключом 256 бит.

### Функции и структуры данных

#### `PI: Tuple[int, ...]` и `PI_INV: Tuple[int, ...]`
* **Назначение**: Константные таблицы прямой ($\pi$) и обратной ($\pi^{-1}$) 8-битных подстановок (S-блоки), определенные в разделах 4.1 и 4.2 RFC 7801.

#### `GF_MULT: List[List[int]]`
* **Назначение**: Предвычисленная таблица умножения в поле Галуа $\mathbb{F}_{2^8} \cong \mathbb{F}_2[x] / (x^8 + x^7 + x^6 + x + 1)$ ($0\text{x}1C3$). Размерность $256 \times 256$.
* **Логика работы**:
  Вспомогательная функция `_gf_mult(a, b)` реализует классический алгоритм умножения многочленов со сдвигом влево и приведением по модулю неприводимого полинома `0x1C3`:
  ```python
  def _gf_mult(a: int, b: int) -> int:
      res = 0
      while b > 0:
          if b & 1:
              res ^= a
          a <<= 1
          if a & 0x100:
              a ^= 0x1C3
          b >>= 1
      return res & 0xFF
  ```

#### `_R(state: bytes) -> bytes` и `_R_inv(state: bytes) -> bytes`
* **Сигнатура**: `(bytes) -> bytes` (длина ровно 16 байт).
* **Назначение**: Прямое и обратное элементарное преобразование сдвигового регистра.
* **Логика**: Вычисляет свертку 16 байтов входного состояния с константным вектором `L_VEC` в поле $\mathbb{F}_{2^8}$ через `GF_MULT`, после чего сдвигает байты вправо.

#### `_L(state: bytes) -> bytes` и `_L_inv(state: bytes) -> bytes`
* **Сигнатура**: `(bytes) -> bytes`.
* **Назначение**: Полное линейное преобразование блока.
* **Логика**: Представляет собой 16-кратное последовательное применение отображения `_R` (или `_R_inv`).

#### `_F(k: bytes, a1: bytes, a0: bytes) -> Tuple[bytes, bytes]`
* **Сигнатура**: `(bytes, bytes, bytes) -> Tuple[bytes, bytes]` (каждый аргумент по 16 байт).
* **Назначение**: Раундовая ступень сети Фейстеля для развертывания ключей.
* **Логика**:
  $$a_1' = L(S(a_1 \oplus k)) \oplus a_0, \quad a_0' = a_1$$

#### Класс `Kuznyechik(key: bytes)`
* `__init__(self, key: bytes)`: Принимает 32-байтный ключ. Вызывает `_expand_keys(key)`, формируя список из 10 раундовых ключей `self.round_keys` ($K_1, \dots, K_{10}$).
* `encrypt_block(self, block: bytes) -> bytes`:
  Шифрует один 16-байтный блок открытого текста. Выполняет 9 раундов $L \circ S \circ X[K_i]$ и финальное наложение десятого ключа $X[K_{10}]$.
* `decrypt_block(self, block: bytes) -> bytes`:
  Расшифровывает один 16-байтный блок, применяя обратные операции в обратном порядке: $X[K_1] \circ \prod_{i=2}^{10} (S^{-1} \circ L^{-1} \circ X[K_i])$.
* `encrypt_cbc(self, plaintext: bytes, iv: bytes = None) -> bytes`:
  Симметричное шифрование произвольного объема данных в режиме CBC.
  1. Если `iv` не передан, генерируется `os.urandom(16)`.
  2. Данные дополняются набивкой PKCS#7: $pad = 16 - (\text{len} \bmod 16)$, добавляется $pad$ байт со значением $pad$.
  3. Каждый блок перед шифрованием складывается по XOR с предыдущим шифроблоком.
  4. Возвращает `iv + ciphertext`.
* `decrypt_cbc(self, ciphertext: bytes) -> bytes`:
  Снимает префикс `iv` (первые 16 байт), производит блочное расшифрование, удаляет байты дополнения PKCS#7 с валидацией корректности набивки.
* `encrypt_ctr(self, plaintext: bytes, iv: bytes = None) -> bytes`:
  Шифрование в режиме счетчика (CTR). Генерирует гамму шифра путем шифрования последовательно инкрементируемых блоков `iv[:8] + counter.to_bytes(8, 'big')` и складывает ее по XOR с открытым текстом.
* `decrypt_ctr(self, ciphertext: bytes) -> bytes`:
  В режиме CTR дешифрование тождественно шифрованию той же псевдослучайной гаммой.

## 2.2. Модуль `crypto/streebog.py`

Реализует стандарт хеширования ГОСТ Р 34.11-2012 («Стрибог») на 512 и 256 бит, а также механизмы HMAC и PBKDF2.

### Функции и структуры данных

#### Таблицы `TAU`, `MATRIX_A`, `TABLE_L`
* `TAU`: Таблица байтовой перестановки $P$ (RFC 6986, раздел 6.3).
* `MATRIX_A`: 64 строки 64-битных целых чисел, задающих матрицу линейного преобразования $L$ над полем $\mathbb{F}_2$.
* `TABLE_L`: Трехмерный оптимизированный массив предвычисленных значений $L$-преобразования, позволяющий заменять битовые матричные умножения быстрыми табличными выборками побайтово.

#### Класс `_StreebogState(digest_size: int = 512)`
* `update(data: bytes)`: Буферизует входной поток данных. При накоплении 64 байт (512 бит) передает блок в функцию сжатия `_g_N()`, инкрементируя счетчик обработанных бит $N$ и контрольную сумму $\Sigma$ в кольце $\mathbb{Z}_{2^{512}}$.
* `digest() -> bytes`: Выполняет финализацию: дополняет остаток буфера битом `1` и нулями, сжимает последний блок, сжимает блок длины сообщения $|M|$ и финализирует контрольной суммой $\Sigma$. Возвращает 64 байта (для 512 бит) или младшие 32 байта (для 256 бит).

#### `streebog512(data: Union[str, bytes]) -> bytes`
* **Назначение**: Вычисление 512-битного криптографического хеша (64 байта).

#### `streebog256(data: Union[str, bytes]) -> bytes`
* **Назначение**: Вычисление 256-битного криптографического хеша (32 байта).

#### `hmac_streebog512(key: bytes, message: bytes) -> bytes`
* **Сигнатура**: `(bytes, bytes) -> bytes` (возвращает 64 байта).
* **Логика**: Реализует стандартную схему HMAC по RFC 2104:
  $$K' = \begin{cases} \text{streebog512}(K), & \text{если len}(K) > 64 \\ K \parallel 0^{64 - \text{len}(K)}, & \text{иначе} \end{cases}$$
  $$\text{HMAC} = \text{streebog512}((K' \oplus 0x5C) \parallel \text{streebog512}((K' \oplus 0x36) \parallel message))$$

#### `pbkdf2_streebog512(password: Union[str, bytes], salt: bytes, iterations: int = 1000, dklen: int = 64) -> bytes`
* **Сигнатура**: `(Union[str, bytes], bytes, int, int) -> bytes`.
* **Логика**: Вырабатывает ключ заданной длины `dklen`, используя `hmac_streebog512` в качестве псевдослучайной функции $PRF$. Применяется для хеширования паролей и деривации ключей шифрования.

## 2.3. Модули `crypto/rsa32k.py` и `crypto/rsa_parallel.py`

Обеспечивают генерацию, экспорт, импорт, дополнение и гибридное шифрование для ключей RSA стандартных (2048, 4096) и экстремальных (32768) размеров.

### Функции `crypto/rsa32k.py`

#### `build_rsa_keypair_from_primes(p: int, q: int, public_exponent: int = 65537) -> Tuple[rsa.RSAPrivateKey, rsa.RSAPublicKey]`
* **Входные параметры**:
  * `p`, `q`: простые числа (типа Python `int` произвольной разрядности).
  * `public_exponent`: открытая экспонента $e$ (по умолчанию 65537).
* **Возвращаемое значение**: кортеж `(private_key, public_key)` интерфейса библиотеки `cryptography`.
* **Внутренняя логика**:
  1. Проверяет условие $p > q$. Если $p < q$, значения меняются местами для соответствия стандарту PKCS#1.
  2. Вычисляет модуль $n = p \cdot q$.
  3. Вычисляет функцию Эйлера $\varphi(n) = (p - 1)(q - 1)$.
  4. Находит секретную экспоненту $d = \text{pow}(e, -1, \varphi(n))$.
  5. Рассчитывает CRT-параметры: $dmp1 = d \bmod (p - 1)$, $dmq1 = d \bmod (q - 1)$, $iqmp = \text{pow}(q, -1, p)$.
  6. Конструирует структуры `RSAPublicNumbers` и `RSAPrivateNumbers` и инициализирует объект ключа через OpenSSL backend.

#### `generate_rsa_keypair(key_size: int = 32768, public_exponent: int = 65537) -> Tuple[...]`
* **Логика**: Прямой вызов системного генератора `rsa.generate_private_key`. Для ключей до 4096 бит выполняется мгновенно; для 32768 бит рекомендуется использовать многопоточный генератор.

#### `get_or_create_rsa_keypair(key_size: int = 4096) -> Tuple[...]`
* **Логика**: Для размера 32768 бит проверяет наличие предвычисленного файла в пуле `data/rsa_pool/precomputed_32k.json`. Если файл найден, ключ загружается за 0.05 с. В противном случае генерируется на лету.

#### `rsa_encrypt_hybrid(public_key: rsa.RSAPublicKey, plaintext: Union[str, bytes]) -> str`
* **Логика**:
  1. Генерирует 32-байтный случайный сессионный ключ $K_{\text{sess}}$ и 16-байтный $IV$.
  2. Шифрует открытый текст $M$ с помощью `Kuznyechik(K_sess).encrypt_ctr(plaintext, iv=iv)`.
  3. Шифрует сессионный ключ $K_{\text{sess}}$ с помощью `public_key.encrypt(K_sess, padding.OAEP(MGF1(SHA256), SHA256))`.
  4. Сериализует компоненты в JSON-бандл и кодирует в Base64.

#### `rsa_decrypt_hybrid(private_key: rsa.RSAPrivateKey, encrypted_bundle_str: str) -> bytes`
* **Логика**:
  1. Десериализует JSON-бандл.
  2. Расшифровывает `enc_key` закрытым ключом RSA с набивкой OAEP-SHA256, восстанавливая $K_{\text{sess}}$.
  3. Дешифрует тело шифротекста симметричным шифром «Кузнечик» в режиме CTR.

### Функции `crypto/rsa_parallel.py`

#### `find_prime_parallel(prime_bits: int, num_workers: int = None, progress_callback = None) -> Tuple[int, int, float]`
* **Назначение**: Многопроцессорный поиск одного простого числа заданной битовой длины `prime_bits`.
* **Логика**:
  1. Создает пул из `num_workers` процессов `mp.Process`, разделяемый счетчик протестированных кандидатов `mp.Value("q")` и потокобезопасную очередь результата `mp.Queue`.
  2. Воркер в цикле генерирует кандидатов с установленными двумя старшими битами, отсекает их малым решетом и проверяет тестом Миллера — Рабина.
  3. При нахождении простого числа устанавливается флаг `stop_event`, оставшиеся воркеры останавливаются, результат возвращается в вызывающий поток.

#### `generate_rsa_keypair_parallel(key_size: int = 4096, num_workers: int = None, verbose: bool = True) -> Tuple[...]`
* **Логика**:
  1. Запускает `find_prime_parallel` для генерации $p$ длины `key_size // 2`.
  2. Запускает `find_prime_parallel` для генерации $q$, гарантируя $q \neq p$ и $(p \cdot q).\text{bit\_length}() == \text{key\_size}$.
  3. Собирает RSA-ключ через `RSAPrivateNumbers`.

## 2.4. Модуль `crypto/ecp.py`

Реализует электронную цифровую подпись (ЭЦП) и цифровые сертификаты.

### Функции модуля

#### `generate_ecp_keypair() -> Tuple[ec.EllipticCurvePrivateKey, ec.EllipticCurvePublicKey]`
* **Логика**: Генерирует ключевую пару на стандартной эллиптической кривой SECP384R1 (NIST P-384).

#### `issue_self_signed_certificate(...) -> Dict[str, Union[str, int]]`
* **Входные параметры**: `username`, `user_id`, `private_key`, `public_key`, `valid_days=365`.
* **Логика**:
  1. Формирует структуру сертификата с уникальным серийным номером (UUID4) и датами действия.
  2. Вычисляет канонический JSON-дайджест структуры через `streebog512`.
  3. Накладывает подпись закрытым ключом ECDSA.
  4. Добавляет подпись в поле `signature` в Base64.

#### `verify_certificate(cert_data: Dict) -> bool`
* **Логика**: Извлекает подпись, восстанавливает канонический дайджест оставшихся полей по «Стрибог-512» и выполняет верификацию открытым ключом, указанным в самом сертификате.

#### `sign_message(private_key: ec.EllipticCurvePrivateKey, message: Union[str, bytes]) -> str`
* **Логика**: Хеширует входное сообщение через `streebog512`, вычисляет подпись ECDSA и возвращает ее в кодировке Base64.

#### `verify_message_signature(public_key: ec.EllipticCurvePublicKey, message: Union[str, bytes], signature_b64: str) -> bool`
* **Логика**: Проверяет подлинность переданной подписи `signature_b64` относительно открытого текста `message` и открытого ключа `public_key`.

## 2.5. Модуль `crypto/db_cipher.py`

Обеспечивает прозрачное шифрование полей базы данных при хранении (Encryption at Rest).

### Функции модуля

#### `encrypt_db_field(value: Optional[Union[str, bytes]]) -> Optional[str]`
* **Логика**: Принимает открытый текст. Если аргумент равен `None`, возвращает `None`. Иначе шифрует данные симметричным шифром «Кузнечик» в режиме CBC с динамическим вектором инициализации $IV$ на мастер-ключе `_DB_MASTER_KEY`. Возвращает строку Base64.

#### `decrypt_db_field(enc_value: Optional[str]) -> Optional[str]`
* **Логика**: Декодирует Base64, расшифровывает через `Kuznyechik.decrypt_cbc` и возвращает исходную строку в UTF-8.

# Глава 3. Сервисный уровень (Service Layer)

## 3.1. Модуль `services/auth_service.py`

Оркестрирует регистрацию, валидацию входных параметров и прохождение 3FA.

### Внутренние хранилища состояний:
* `PENDING_3FA_SESSIONS: Dict[str, Dict]`: сессии между фактором 1 и фактором 2/3.
* `PENDING_RESET_SESSIONS: Dict[str, Dict]`: сессии сброса забытого пароля.

### Основные функции:

#### `validate_registration_inputs(username: str, email: str, password: str) -> Tuple[bool, Optional[str]]`
* Проверяет соответствие логина правилу `^[a-zA-Z0-9_-]{3,20}$`.
* Проверяет корректность email по RFC-совместимому регулярному выражению.
* Проверяет сложность пароля: длина 8–64 символа, наличие строчных, прописных букв, цифр и специальных знаков (`@$!%*?&_\-#^`).

#### `register_user(db: Session, username: str, email: str, password: str, rsa_key_size: int = 4096) -> Tuple[Optional[User], Optional[str]]`
* Выполняет проверку уникальности логина и email в БД.
* Вырабатывает соль и вычисляет хеш пароля через `pbkdf2_streebog512`.
* Генерирует ключевые пары ЭЦП и RSA, сертификат ЭЦП и список кодов восстановления.
* Создает и сохраняет сущность `User`.

#### `start_3fa_login(db: Session, login_input: str, password: str) -> Tuple[Optional[str], Optional[User], Optional[str]]`
* **Фактор 1**: Находит пользователя по логину или email. Вычисляет PBKDF2-Стрибог-512 от введенного пароля и сохраненной соли, сверяет с эталонным хешем.
* Генерирует 6-значный цифровой код OTP (`secrets.randbelow`).
* Отправляет OTP по электронной почте через локальный сервис `mail_server.send_system_email`.
* Регистрирует сессию в `PENDING_3FA_SESSIONS` с временем жизни 300 секунд. Возвращает `session_id`.

#### `verify_3fa_factor2(session_id: str, otp_code: str) -> Tuple[bool, Optional[str]]`
* **Фактор 2**: Сверяет введенный OTP-код с сохраненным в сессии и проверяет, не истекло ли время действия.

#### `verify_3fa_factor3(session_id: str, code: str, db: Session) -> Tuple[Optional[User], Optional[str]]`
* **Фактор 3**:
  1. Пытается проверить переданный код как динамический TOTP (RFC 6238) с использованием функции `verify_totp_code()`.
  2. Если TOTP не подошел, проверяет код по списку одноразовых резервных кодов `user.recovery_codes_list`. При совпадении удаляет использованный код из списка и обновляет запись в БД.
  3. При успехе удаляет сессию из `PENDING_3FA_SESSIONS` и возвращает авторизованного пользователя.

## 3.2. Модуль `services/message_service.py`

Обеспечивает сквозной цикл шифрования, дешифрования и валидации целостности сообщений.

### Основные функции:

#### `send_message(db: Session, sender: User, recipient_id: int, subject: str, body: str, encryption_type: str) -> Tuple[Optional[Message], Optional[str]]`
* Проверяет права отправителя.
* Накладывает цифровую подпись ЭЦП на исходное тело сообщения `body.encode("utf-8")`.
* Вызывает криптографический адаптер:
  * Для `RSA-*`: `rsa_encrypt_hybrid(rsa_pub, body_bytes)`.
  * Для `STREEBOG-512`: `encrypt_message_streebog(body_bytes)`.
  * Для `KUZNYECHIK-256`: `encrypt_message_kuznyechik(body_bytes)`.
* Записывает сообщение в базу данных. Поля `subject`, `ciphertext`, `key_bundle` шифруются симметрично на уровне модели.

#### `decrypt_message_content(db: Session, message: Message, user: User) -> Tuple[Optional[str], bool, str]`
* **Контроль доступа**: Проверяет, является ли запрашивающий пользователь отправителем, получателем или администратором системы (`admin`).
* **Дешифрование**:
  * Для `RSA-*`: Загружает закрытый ключ получателя `recipient.rsa_private_key`, расшифровывает через `rsa_decrypt_hybrid`.
  * Для `STREEBOG-512`: Проверяет валидность имитовставки `calc_hmac == expected_hmac` через `hmac_streebog512`, расшифровывает тело в режиме CTR шифром «Кузнечик».
  * Для `KUZNYECHIK-256`: Расшифровывает в режиме CBC шифром «Кузнечик».
* **Верификация ЭЦП**:
  * Извлекает открытый ключ отправителя (из профиля или снапшота сертификата `message.ecp_cert_snapshot`).
  * Вызывает `verify_message_signature(pub_ecp, decrypted_bytes, message.ecp_signature)`.
  * Возвращает кортеж: `(расшифрованный_текст, статус_подписи_bool, текстовый_комментарий)`.

## 3.3. Модуль `services/crypto_task_service.py`

Управляет фоновым пулом потоков для вычисления и мониторинга тяжелых криптографических операций.

### Основные структуры:
* `CRYPTO_TASKS: Dict[str, Dict[str, Any]]`: Словарь текущих и завершенных фоновых задач.
* `DECRYPTED_MEMORY_CACHE: Dict[Tuple[int, int], Dict[str, Any]]`: Оперативный кэш расшифрованных сообщений в оперативной памяти сервера `(user_id, message_id) -> data`. Предотвращает повторное ресурсоемкое дешифрование при навигации в интерфейсе.

### Основные функции:

#### `start_encryption_task(user_id, recipient_id, subject, body, encryption_type) -> str`
* Создает дескриптор задачи со статусом `pending`.
* Запускает рабочий поток `threading.Thread(target=_run_encryption_worker, daemon=True)`.
* Возвращает строковый идентификатор задачи `task_id`.

#### `start_decryption_task(user_id, message_id) -> str`
* Создает задачу дешифрования и запускает рабочий поток `_run_decryption_worker`.

#### `_run_encryption_worker(task_id, ...)` и `_run_decryption_worker(task_id, ...)`
* Выполняют поэтапную имитацию и расчет криптографических преобразований с обновлением полей `progress`, `stage`, `current_iteration`, `candidates_tested` и `elapsed_seconds`.
* В финале вызывают `send_message` или `decrypt_message_content`, сохраняют результат в кэш и переводят задачу в статус `completed`.

## 3.5. Модуль `services/mail_server.py`

Встроенный сервер протокола SMTP (RFC 5321), обеспечивающий автономную доставку одноразовых паролей без внешних сетевых зависимостей.

### Основные классы и функции:
* `LocalSMTPProtocol(asyncio.Protocol)`: Реализует конечный автомат команд протокола SMTP: `HELO/EHLO`, `MAIL FROM`, `RCPT TO`, `DATA`, `QUIT`.
* `LocalSMTPServer`: Управляет жизненным циклом сокета сервера на `127.0.0.1:1025`. Запускается в lifespan веб-приложения FastAPI.
* `send_system_email(to_email: str, subject: str, body: str) -> bool`: Отправляет письмо через локальный SMTP-клиент `smtplib.SMTP('127.0.0.1', 1025)`. При недоступности порта сохраняет письмо непосредственно в журнал `RECEIVED_EMAILS`.

# Глава 4. Утилита командной строки и API-модуль `cli.py`

Консольная утилита `cli.py` обеспечивает прямое терминальное взаимодействие со всеми криптографическими модулями без необходимости запуска веб-сервера.

## 4.1. Новые функции предварительной генерации и сборки ключей

### `generate_and_save_pq(bits=32768, out_dir="data/rsa_pregen", threads=None, verbose=True) -> PregenResult`
* **Назначение**: Многопоточная генерация двух простых чисел $p$ и $q$ (по `bits // 2` бит) и сохранение их на диск.
* **Поток данных**:
  1. Определяет число рабочих потоков `threads` (по умолчанию равно числу логических ядер CPU, например 16).
  2. Запускает `find_prime_parallel` для генерации $p$.
  3. Запускает `find_prime_parallel` для генерации $q$, контролируя $q \neq p$ и точность результирующей длины произведения $(p \cdot q).\text{bit\_length}() == bits$.
  4. Гарантирует $p > q$.
  5. Создает каталог `out_dir` (по умолчанию `data/rsa_pregen`).
  6. Сохраняет:
     * `primes.json` и `rsa32k_primes.json` (метаданные, $p$, $q$, hex-представления, время генерации, число кандидатов);
     * `p.txt` и `q.txt` (чистые числовые значения).
  7. Возвращает объект `PregenResult` (поддерживает доступ по ключам словаря и распаковку в кортеж `p, q, path`).

### `load_pregen_primes(source="data/rsa_pregen") -> Tuple[int, int]`
* **Назначение**: Универсальная загрузка ранее сгенерированных параметров $p$ и $q$ из каталога или отдельного файла.
* **Логика разрешения путей**:
  1. Если `source` — каталог: последовательно ищет файлы `primes.json`, `rsa32k_primes.json`, `pq.json`, `primes_32k.json` либо пару `p.txt` и `q.txt`.
  2. Если `source` — файл: парсит JSON либо текстовый файл с построчной записью чисел.
  3. Поддерживает как десятичные строковые представления, так и шестнадцатеричные (`0x...`).

## 4.2. Диспетчер команд `cmd_rsa(args)`
* Поддерживает флаг `--generate` с опциональным указанием `--pregen`:
  * При наличии `--pregen`: параметры $p$ и $q$ считываются из `data/rsa_pregen`, ключевая пара собирается за сотые доли секунды через `build_rsa_keypair_from_primes(p, q)`.
  * При отсутствии `--pregen`: запускается честный многопоточный поиск сомножителей на всех ядрах CPU «на лету» через `generate_rsa_keypair_parallel()`.
* Поддерживает операции `--encrypt` (гибридное шифрование открытым ключом) и `--decrypt` (расшифрование закрытым ключом).

## 4.3. Демонстрационные команды
* `demo-rsa-4k`: Быстрая сквозная демонстрация RSA-4096 (генерация, шифрование, расшифрование, проверка совпадения).
* `demo-rsa-32k`: Демонстрация экстремального RSA-32K (поддерживает флаг `--pregen` для мгновенного запуска).
* `kuznyechik --demo`: Проверка эталонного примера RFC 7801.
* `streebog --demo`: Проверка эталонного тестового вектора RFC 6986.
